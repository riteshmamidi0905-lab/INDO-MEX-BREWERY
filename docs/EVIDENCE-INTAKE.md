# Evidence intake: where each real input goes (one page; no new databases)
When a real input arrives, send it to Claude as it is. Claude files it with the tool below, keeps the original untouched, and never fills a gap with a guess (missing = NOT MEASURED / NOT PROVIDED). Nothing here is populated today; every file named is a header-only template or an existing recorder.

## Say "INGEST THESE": what happens (Sprint 21)
Send receipt, package and label photos (and quote files or raw professional replies) in one message. Claude (1) runs `python3 tools/intake.py preserve <kind> <files>` so the originals are kept read-only with SHA-256, (2) reads the images directly and fills an observed-fields JSON: only what is visible (store, date, item, brand, package size, price, tax, lot or best-by, D-54 label result); everything else is NOT OBSERVED, (3) runs `record-purchase` and, where a pack size and price are readable, `apply-prices` (price class RETAIL RECEIPT), and (4) asks only for what is missing and matters. You never edit a CSV. Routing for every input kind: `python3 tools/intake.py route`. A retail receipt, directory listing, search snippet or assumption is never recorded as a QUOTE.

## First provisional dish cost from Session 1 receipts (the shortest path)
1. Receipts and labels ingested (above): purchase price, pack size, brand, date. 2. Measured yields from Session 1 (raw to trimmed to cooked weights; tortilla to finished chip weight) go into `food/costing/ingredients.csv` (yield_pct 0-100). 3. The frozen portion weights (chicken 120 g, chips 60 g, crema 20 g and the garnish amounts) are the portion quantities; enter them in `food/costing/recipes.csv` only from the real cook. 4. `python3 tools/food_costing.py` then prints an ingredient-only cost per portion and flags non-quote prices as R&D. Keep four things separate and never blend them: **FOOD COST** (ingredients only, as above); **DIRECT VARIABLE COST** (oil allocation, packaging, payment fees, direct event labour: only from real inputs); **CONTRIBUTION MARGIN** (price minus food cost minus direct variable cost: needs a real price); **FULL BUSINESS PROFITABILITY** (rent, salaried labour, overhead, debt: not computable yet). Missing inputs stay blank; the tool reports NOT COSTABLE.
