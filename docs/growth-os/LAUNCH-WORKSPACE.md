# Business-launch workspace (Milestone 3)

Industry-agnostic. Flagship case study: **NASHA — The Courtyard** (a proposed hospitality brand, not an operating business). Second tenant: Meridian Fitness (a second studio). Both synthetic.

* **Model (migration 109, tenant-scoped, RLS, audited):** projects (name, industry, location, concept, budget, target date, stage), assumptions (origin: founder / synthetic assumption / public reference), milestones, research findings (source kind, URL, retrieval date, confidence, mandatory limitation), suppliers, supplier products (price class), shortlists, financial scenarios (inputs hash + results), procurement recommendations (governed state machine) and launch events (append-only).
* **Supplier honesty by constraint:** no e-mail address or phone number can be stored; `verified_public` needs official website + source URL + date; a price needs a price class and `NONE_PUBLISHED` forbids one; real quotes need a source and a date; synthetic fixtures must say so. Freshness (fresh/aging/stale/unverified) is computed from the verification date.
* **Data in the repository today:** three REAL supplier *leads* (Farm to Table LLC, Hill Country Dairies, Brothers Produce) found through public web search on 2026-10-23, each with the page that mentions it. They are `lead_unverified`: official websites not verified, no contact, no prices. All compared prices belong to the repository's existing SYNTHETIC quote fixtures. **External verification is incomplete**; nothing was contacted.
* **Financial plan (`financials.py`):** unit costs, gross and contribution margins, fixed costs, break-even, payback, runway, price sensitivity with a stated elasticity, scenario comparison; deterministic, hashed inputs, recomputable; everything labelled simulated.
* **Existing NASHA models reused:** recipe bill of materials (`recipes/bom.py`) for ingredient needs; synthetic supplier quote set (`recipes/suppliers.py`) imported as supplier products; pricing engine (`pricing.py`) for offer economics; menu items and founder-approved concept prices from the Growth OS product tables. Inventory planning (reorder points, weeks covered) is derived from the same plan. Campaign planning = offer economics + draft campaigns (nothing is published).
* **Not connected:** the simulation warehouse's inventory counts and orders (no on-hand stock in Growth OS), real supplier prices, any ordering or contact.
