## 2. What changed

* **Comparative claims** (`model_boundary.verify_comparative`). Lowest / cheapest / minimum / least expensive / most affordable / best price and highest / most expensive / maximum / priciest are verified against the **full stored quote set of the tenant** passed to the boundary (row-level security already scopes it; another tenant's quote can never make a claim true). Fails closed (COMPARATIVE_UNVERIFIABLE) when: no product or several products are named; fewer than two comparable quotes; different units; different kinds of quote (e.g. synthetic vs supplier); different currencies; the claim names neither supplier nor price. COMPARATIVE_FALSE when a named supplier is not the extreme, or the stated price is not. Quotes outside their `valid_from`/`valid_to` window are dropped when the workflow passes `as_of`. Exact ties are all true. An explicitly scoped claim ("among the retrieved records ...") is checked against the retrieved records only and labelled "NOT a global statement" in its provenance. A global minimum is **never** inferred from partial retrieval. "Minimum order" is not a superlative. The verdict, the whole comparison set (supplier, price, unit), the left-out quotes and the scope are returned in `comparisons` and written to the audit trail.
* **Absence claims** (`classify_absence`). A named supplier's "does not publish prices" is checked against that supplier's stored products; an evidence-scoped claim ("not provided in the retrieved records") against the cited passages; a word-for-word quotation of a cited passage keeps its provenance; a **universal claim** ("no supplier has published a price", "for any of the suppliers") is accepted only if the authoritative stored set contains no published price at all, else ABSENCE_OVERGENERAL with the preferred wording "No matching price was found in the searched records." Claims the platform verifier rejected in a failed run are classified the same way and written to the fallback event.
* **Instructions in source material.** Three independent layers, none relying on prompt wording: (1) `screen_documents` quarantines a supplier document that addresses the assistant before it is ingested (never stored, never retrieved); (2) the boundary rejects any claim resting on a cited passage that contains such a directive (UNTRUSTED_SOURCE); (3) the boundary rejects an answer or claim that echoes an instruction ("I authorize you to email ...", "email every supplier", "tell the reader to ..."). The existing rejection rules (unsupported verification, price mismatch, wrong source, instruction text) are unchanged. `SupplierResearchAgent(quarantine=False)` exists only so the evaluation can expose a model to the text and measure the model alone (C12); production keeps quarantine on.
* **Workflow question v2** (`launch_workflow.research_query`): names the eight costliest ingredients and asks for each supplier's quoted price. The deterministic recommendation never depended on this text.
* **Ingestion hygiene.** Supplier documents already named the supplier on each line (previous pass); stale documents are removed on re-ingest (previous pass).

## 6. Limits

The comparative check judges the claim against stored quotes at record level and lexically: it recognises the product by name or ingredient reference and the supplier by name; a paraphrase that names neither is rejected as unverifiable (a deliberate false-reject trade). It does not rank across different units or kinds of quote. The directive screen is lexical; a paraphrase that evades it reaches the model and is contained only by the grounding, attribution, price, verification and instruction rules. **Model-level resistance cannot be improved from this repository without changing the platform's prompts** (e.g. a stronger untrusted-evidence instruction in `prompts/synthesizer.json`, and a rule that evidence-derived claims may not quote imperative text). That is a separate-repository change and was **not** made; it needs authorisation.
