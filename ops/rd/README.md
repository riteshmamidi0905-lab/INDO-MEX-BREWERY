# R&D traceability (structure only; no iterations exist)
Every real prototype gets an ID and a row in `iteration-log.csv`. **Do not create historical or example iterations**: the file stays header-only until a real cook or brew happens.
**IDs:** `FOOD-C65-001` (Chicken 65 Totopos, iteration 1), `FOOD-PANEER-001`, `FOOD-GOAT-001`, `FOOD-GOBI-001`, `FOOD-QUES-001`; beers `BEER-HEFE-001`, `BEER-MXLG-001`, `BEER-VIEN-001`, `BEER-PILS-001`, `BEER-WIT-001`; pairing sittings `PAIR-001`. Increment the last number for each real iteration; a re-run of the same recipe version is a new iteration.
**Each row captures:** date, operator, recipe or brief version, ingredient lots/brands where relevant, process, key temperatures, timings, yield, photo IDs, tasters (count and roles), scores, deviations, failures, decision (KEEP/REWORK/HOLD/CUT or PROVISIONAL LEADER as the recorders define), next iteration. Detailed measurements still go to the recorders (`food/t1-results/`, `food/sessions/results.csv`); this log is the index that ties them together. Frozen gates are never edited after tasting (D-74, D-76).
