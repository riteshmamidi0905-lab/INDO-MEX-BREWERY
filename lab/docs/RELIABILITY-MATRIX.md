# Reliability matrix: failure catalog (FC-01..FC-19) and gaps (GAP-01..GAP-10)

**SYNTHETIC DATA / SIMULATED OPERATION / OFFLINE EVALUATION / NOT PRODUCTION DEPLOYED.** Every entry concerns the synthetic NASHA lab. Nothing is a production incident or measured production reliability. Source catalog: the private career-evidence `evidence/FAILURE-CATALOG.md` (read only). Measured values come from `lab/results/ops/*.json`, produced by `python -m nasha_lab.ops.evaluate_ops ...` (see `OPS-CONTROL-CENTER.md` section 10). Test ids are `file::test`.

Status vocabulary: **COVERED** (a regression test and a measured result exist), **PARTIAL** (covered with a stated hole), **NOT APPLICABLE** (with reason), **NOT DONE** (with reason). Resilience features marked *opt-in* are wrappers: the stock service does not use them unless the caller wires them in.

## C. What is not done and why

* Concurrency and load testing (GAP-02): the agent service serialises runs behind a lock and the execute wrapper is process-global; a concurrent test would need design work first.
* A real killed process, a real MCP server crash, a real database server: nothing like them exists in this environment (no Docker daemon). The faults are injected at in-process seams.
* Conflict detection between two authoritative documents (GAP-03) and surfacing excluded sources at the tool boundary: not implemented, because both need changes to frozen-adjacent knowledge/tool code; reported as a gap instead of patched.
* A real language model: none runs locally; model faults use scripted stand-ins, and recorded real-model numbers are quoted only from `results/`.
