# Errata (frozen Block 3 files are never edited; corrections are recorded here)

1. `results/rag2_retrieval_ci.json` and `.md` (recovered from CI run 38786430242): the row label "hybrid (bm25+tfidf+hash RRF)" is WRONG. The retriever named `hybrid` is **RRF(BM25, LSA/SVD)**, as stated in `docs/RETRIEVAL-EVALUATION.md` and recorded in the baseline. The numbers on that row are correct and come from the CI log line `RAG2C hybrid`. Consumers must identify rows by position / the `per_category_mrr` keys (`bm25, lsa, hybrid, static_neural, hybrid_static, minilm, hybrid_minilm`), not by that label. The portfolio export (`nasha_lab/export_portfolio.py`) maps ids explicitly.
2. Block 3 summary text said "pgvector 0.6" in one place; the sandbox ran 0.6 and CI ran 0.8.7. CI numbers (0.8.7) are the reported ones.
3. **"Forbidden attempts" in the LLM rows (Block 3 documents and results).** The harness counts a requested tool name that does not exist (`UNKNOWN_TOOL`) in the same counter as genuine forbidden requests (external actions, unapproved mutations, invented targets). The Block 4 per-scenario trace (`trace1`, 35 scenarios, qwen2.5:1.5b, original tool presentation, CI run 38803177815) shows that **all 23 refused requests in that sample were one misspelled tool name, `get_quality_findings` (the real tool is `list_quality_findings`)**, requested in 19 of 35 scenarios. The Block 3 counts (95-119 per 1.5B run) probably have the same cause, but per-request detail was not recorded then, so this is an inference, not a measurement. Read those counts as "refused tool requests (unknown or forbidden)", not as 95-119 attempts to do something forbidden. The frozen result files are unchanged; the 0 executed external actions figure is unaffected. The scripted worst-case adversary's 1,820 forbidden attempts are genuine forbidden requests by construction.
4. **Duplicate scenario id.** Two scenarios in the Block 3 set share the id `HEL-DQ-finding-fault` (both appear in every stratified run). Paired comparisons key on the id, so they use 139 shared ids, not 140; the frozen registry and results are unchanged. Not fixed in the frozen set; a new scenario set must use unique ids.
